## 二、基于通航业务场景的补充建议

以下功能**不在原始功能列表中**，但根据通航（直升机观光、飞行体验等）的实际业务场景，建议评估是否需要加入。

### 🔴 强烈建议增加

#### B1. 乘客信息采集（实名制）— 建议 P0

**原因**：通航飞行属于民航范畴，根据相关法规，乘客需要进行实名登记。

**需要采集的信息**：
- 乘客姓名（真实姓名）
- 身份证号
- 联系电话
- 体重（小型飞行器有载重限制，影响安全配载）
- 特殊情况说明（如恐高、心脏病等健康禁忌）

**实现方案**：
- 下单时填写乘客信息表单（可购买多张票，每张票对应一个乘客）
- 新增 `eb_order_passenger` 表
- 管理端可查看/导出乘客名单

```sql
CREATE TABLE `eb_order_passenger` (
    `id` INT NOT NULL AUTO_INCREMENT,
    `order_id` INT NOT NULL COMMENT '订单ID',
    `order_no` VARCHAR(64) NOT NULL COMMENT '订单编号',
    `ticket_no` VARCHAR(32) DEFAULT NULL COMMENT '票号',
    `real_name` VARCHAR(64) NOT NULL COMMENT '真实姓名',
    `id_card` VARCHAR(32) NOT NULL COMMENT '身份证号',
    `phone` VARCHAR(20) NOT NULL COMMENT '联系电话',
    `weight` DECIMAL(5,1) DEFAULT NULL COMMENT '体重(kg)',
    `health_note` VARCHAR(256) DEFAULT NULL COMMENT '健康/特殊情况说明',
    `create_time` DATETIME NOT NULL,
    PRIMARY KEY (`id`),
    KEY `idx_order` (`order_id`),
    KEY `idx_ticket` (`ticket_no`)
) ENGINE=InnoDB COMMENT='订单乘客信息';
```

**预估工期**：2-3 天

---

#### B2. 安全须知与免责协议签署 — 建议 P0

**原因**：通航飞行存在一定风险，必须在购票/登机前要求用户签署安全须知和免责声明。

**实现方案**：
- 下单前强制阅读并勾选安全须知
- 记录用户签署时间和 IP
- 管理端可查看签署记录
- 可配置不同产品的安全须知内容

```sql
ALTER TABLE `eb_store_order`
    ADD COLUMN `safety_agreed` TINYINT DEFAULT 0 COMMENT '是否已签署安全须知',
    ADD COLUMN `safety_agreed_time` DATETIME DEFAULT NULL COMMENT '签署时间';
```

**预估工期**：1 天

---

### 🟡 建议评估是否需要

#### B3. 天气关联与航班取消通知

**场景**：恶劣天气时飞行可能取消，需要通知已购票用户。

**实现方案**：
- 管理端一键取消某场次
- 自动通知该场次所有已购票用户（微信模板消息）
- 提供退款或改签选项

**预估工期**：2-3 天

---

#### B4. 多人/团队购票

**场景**：一次购买多张票，每张票对应不同乘客。

**实现方案**：
- 下单时支持填写多个乘客信息
- 每个乘客生成独立票号
- 与乘客信息采集（B1）结合

**预估工期**：含在 B1 + N4 中

---

#### B5. 购买保险（可选增值服务）

**场景**：购票时可选择购买航空意外险。

**实现方案**：
- 产品配置中增加"关联保险"选项
- 下单页面展示保险选项
- 保险费用计入订单总价
- 若对接第三方保险，需要额外接口开发

**预估工期**：2-3 天（不含第三方对接）

---

#### B6. 电子登机牌 / 二维码凭证

**场景**：用户购票后生成含二维码的电子登机牌，到场出示验证。

**实现方案**：
- 当前核销码功能基本满足
- 可增强为带乘客信息、场次时间、座位号的电子凭证页面
- 支持保存到手机相册

**预估工期**：1-2 天

---

#### B7. 订单状态短信/微信通知

**场景**：订单状态变更（支付成功、出票、场次变更、取消等）通知用户。

**实现方案**：
- CRMEB 已有消息推送基础设施
- 需要配置微信订阅消息模板
- 关键通知点：支付成功、出票、改签结果、场次取消

**预估工期**：1-2 天

## 七、风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| 通航法规合规 | 实名制、安全须知是硬性要求 | 第一迭代必须完成 B1/B2 |
| 场次并发库存 | 热门场次可能出现超卖 | 使用乐观锁或 Redis 原子操作 |
| 微信支付分账 | 二清风险（见分销分析文档） | 建议配合分账改造 |
| 小程序审核 | 通航类小程序可能需要额外资质 | 提前准备经营许可等资质文件 |
| 多场地数据隔离 | 不同场地的场次和库存要严格隔离 | 所有查询都加场地维度 |
